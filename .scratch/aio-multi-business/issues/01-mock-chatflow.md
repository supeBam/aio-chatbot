# 三事件、显式状态与自然语言流式工作流

状态：已完成

## 范围

实现 [原型规格](../spec.md)，不替换现有 BN 测试导出文件。
入口只使用三个事件和逗号分隔的可售编号，不接收查询状态。
将总状态拆为明确的会话变量，实现有证据的用户背景更新。
回复直接流式输出自然语言，表单 Code 动作作为独立信号先于话术。
完整变量、对象和节点输出见 [字段说明](../fields.md)。

## 验收条件

- BN 不能推荐模拟地址查询范围之外的套餐。
- 明确区分缺少地址、查询结果为空和查询失败。
- 地址变化后旧推荐失效，但不删除用户偏好。
- MS 和 XE 无需地址即可使用。
- 多业务需求和业务澄清信息可以跨轮次保留。
- 机器可识别的动作不依赖自然语言识别。
- 地址完成但需求不足时必须继续访谈，不能仅凭地址、标签数量或模型裸推荐标志跳过。
- 有效标签数组跨轮次复用，普通访谈不重复调用标签接口。
- 需求就绪后一次获取最多 5 款候选详情，再精选最多 3 款。
- 后端返回缺项、越界编号、重复编号或缺失原文时明确阻止推荐。
- 生成文件和针对性测试可以复现。
- `address_add` 和 `address_change` 均重新加载标签，旧推荐失效但偏好和背景保留。
- `context_update` 与标签同次提取，证据错误或需要澄清时不提交变更。
- 表单动作先于回复模型，聊天 Answer 直接引用 LLM，不经过 JSON 包装。
- 回复结束后保存实际上下文，前后端等待本轮工作流完成再执行下一轮。
